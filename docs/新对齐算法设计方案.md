# 新对齐算法设计方案

## 一、方案梳理与完善

### 1.1 核心设计理念

**双链结构**：维护一个对齐结果列表（双链），每个元素表示一个对齐关系，确保：
- 左右两个文件的所有句子都被包含（不遗漏、不重复）
- 保持句子序列的连贯性
- 通过索引关系追踪句子的对应关系

### 1.2 数据结构设计

#### 对齐项（AlignmentItem）结构
```python
{
    'type': 'match' | 'delete' | 'insert' | 'movein' | 'moveout',
    'a': str | None,  # 原文句子（原始文本）
    'b': str | None,  # 校对后句子（原始文本）
    'a_indices': List[int] | None,  # 原文句子索引列表（支持多对一）
    'b_indices': List[int] | None,  # 校对后句子索引列表（支持一对多）
    'a_index': int | None,  # 原文句子索引（单个，兼容旧格式）
    'b_index': int | None,  # 校对后句子索引（单个，兼容旧格式）
    'similarity': float | None,  # 相似度值
    'a_line_number': int | None,  # 原文行号
    'b_line_number': int | None,  # 校对后行号
    'a_line_numbers': List[int] | None,  # 原文行号列表
    'b_line_numbers': List[int] | None,  # 校对后行号列表
    'offset': int | None,  # 偏移量（用于分组）
    'group_id': int | None,  # 组ID（用于标识同一组匹配）
}
```

#### 句子数据结构
```python
{
    'text': str,  # 原始文本
    'normalized': str,  # 规范化文本（用于比较）
    'index': int,  # 句子索引
    'line_number': int,  # 行号
    'matched': bool,  # 是否已匹配
}
```

### 1.3 规范化规则

**计算对齐时规范化**（用于相似度计算）：
1. 删除所有空格（包括全角、半角）
2. 英文引号统一改为中文引号：
   - `'` → `'`（左单引号）
   - `'` → `'`（右单引号）
   - `"` → `"`（左双引号）
   - `"` → `"`（右双引号）
3. 统一标点符号（可选）：
   - 英文冒号 `:` → 中文冒号 `：`
   - 英文逗号 `,` → 中文逗号 `，`

**最终结果使用原始文本**：对齐结果中的 `a` 和 `b` 字段始终使用原始文本。

### 1.4 双链维护机制

#### 核心原则
1. **连续性保证**：左右两个文件的句子索引必须连续，不能跳跃
2. **完整性保证**：所有句子都必须在对齐结果中出现（通过match、delete、insert）
3. **偏移量跟踪**：维护当前偏移量 `offset = b_index - a_index`，用于识别匹配组

#### 分组机制
- **匹配组**：偏移量相同的连续match项构成一组
- **组边界**：当偏移量改变时，一组结束，新组开始
- **交叉检测**：如果新组与旧组有交叉（如旧组：3-4, 4-5；新组：6-3），则：
  - 成员较多的一组胜出
  - 成员较少的一组改为movein/moveout

#### 反向处理机制
当完成一组匹配后，如果发现对侧有被跳过的句子，立即反向处理：
- 如果A侧有未处理的句子，检查B侧是否有对应的insert
- 如果B侧有未处理的句子，检查A侧是否有对应的delete

### 1.5 分阶段对齐策略

#### 阶段一：全等匹配（Exact Match）
- **目标**：找到完全相同的句子（规范化后）
- **方法**：直接字符串比较（规范化后）
- **优势**：快速、准确，为后续阶段提供锚点
- **输出**：生成中间结果HTML，便于调试

#### 阶段二：相似度匹配（Similarity Match）
- **目标**：处理未匹配的句子
- **范围**：只处理阶段一未匹配的句子
- **策略**：
  1. 识别连续的处理单元：
     - 连续多条insert（未被match分隔）
     - 连续多条delete（未被match分隔）
  2. 对每个处理单元：
     - 从两侧最上面的条目开始尝试
     - **整体比较**：先比较整个单元
     - **截取比较**：如果整体比较失败，按较短一方的长度从较长一方截取
     - **合并尝试**：如果截取比较成功，继续尝试合并后续句子，直到相似度下降
  3. 多对一和一对多处理：
     - 支持A侧多个句子匹配B侧一个句子
     - 支持A侧一个句子匹配B侧多个句子
     - 暂不考虑多对多（可后续扩展）

### 1.6 交叉匹配处理

**问题**：当出现交叉匹配时（如3-4, 4-5, 6-3），需要判断哪组应该保留。

**解决方案**：
1. **成员数量优先**：成员较多的一组胜出
2. **相似度优先**：如果成员数量相同，选择平均相似度较高的一组
3. **位置优先**：如果前两者相同，选择位置更靠前的一组

**处理流程**：
1. 检测交叉：比较新组与已有组的索引范围
2. 判断胜负：根据上述规则决定保留哪组
3. 修改失败组：将失败组的match项改为movein/moveout

## 八、风险与应对

### 8.1 性能风险
- **风险**：双链维护可能影响性能
- **应对**：优化数据结构，使用索引加速

### 8.2 复杂度风险
- **风险**：算法复杂度较高，难以调试
- **应对**：分阶段开发，每个阶段输出中间结果

### 8.3 准确性风险
- **风险**：新算法可能不如旧算法准确
- **应对**：保留旧算法作为对比，逐步优化

## 九、后续优化方向

1. **多对多匹配**：支持更复杂的匹配关系
2. **语义相似度**：引入更高级的相似度计算
3. **机器学习**：使用ML模型优化匹配
4. **并行处理**：支持大规模文件的并行处理

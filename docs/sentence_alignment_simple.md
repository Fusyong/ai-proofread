# 简单锚点对齐算法说明

## 算法概述

这是一个基于**锚点机制**和**Jaccard相似度**的快速句子对齐算法，适用于改动不大的文本。

## 算法原理

### 核心思想

1. **锚点机制**：在B文本中维护一个当前位置（锚点）
2. **局部搜索**：从A中取一个句子，在B中锚点左右`window_size`范围内搜索最相似的句子
3. **贪心匹配**：如果找到相似度超过阈值的句子，更新锚点到该位置
4. **偏移前进**：处理下一个句子时，锚点从当前位置+`offset`开始

### 算法流程

```
初始化：anchor = 0（B中的起始位置）

对于A中的每个句子：
  1. 在B中[anchor-window_size, anchor+window_size]范围内搜索
  2. 计算与A当前句子的Jaccard相似度
  3. 找到相似度最高的句子
  4. 如果相似度 >= threshold：
      - 标记为匹配
      - 更新 anchor = 匹配位置 + offset
  5. 否则：
      - 标记为删除
      - anchor 保持不变或小幅移动

最后：B中未匹配的句子标记为新增
```

## 相似度算法：Jaccard（基于n-gram）

### 为什么选择Jaccard？

1. **速度快**：只需计算集合的交集和并集
2. **对中文友好**：基于字符n-gram，适合中文文本
3. **实现简单**：代码简洁，易于理解和维护

### Jaccard相似度公式

```
J(A, B) = |A ∩ B| / |A ∪ B|
```

其中A和B是文本的n-gram集合。

### n-gram示例

对于文本"这是句子"（n=2）：
- bigrams: {"这是", "是句", "句子"}

## 参数说明

### 核心参数

- `window_size`（默认10）：搜索窗口大小
  - 锚点左右各搜索`window_size`个句子
  - 值越大，能处理更大的改动，但速度越慢
  - 建议：5-20之间

- `similarity_threshold`（默认0.6）：相似度阈值
  - 超过此值才认为匹配
  - 值越大越严格，可能漏掉一些匹配
  - 建议：0.5-0.7之间

- `ngram_size`（默认2）：n-gram大小
  - 2（bigram）适合中文
  - 3（trigram）更精确但计算稍慢
  - 建议：2

- `offset`（默认1）：锚点偏移量
  - 匹配后，下一个句子的锚点从匹配位置+offset开始
  - 通常设为1（下一个位置）
  - 如果文本改动较大，可以设为0（保持当前位置）

## 优缺点

### 优点

1. **速度快**：时间复杂度 O(n × window_size)，远快于动态规划的 O(n×m)
2. **内存小**：不需要创建巨大的DP表
3. **实现简单**：代码简洁，易于理解和维护
4. **适合改动小的文本**：对于大部分句子不变的场景，效果很好

### 缺点

1. **贪心策略**：可能不是全局最优解
2. **窗口限制**：如果改动超过窗口大小，可能漏掉匹配
3. **顺序敏感**：如果文本顺序变化大，效果会下降
4. **Jaccard限制**：对词序不敏感，可能误匹配结构相似但内容不同的句子

## 适用场景

### 推荐使用

- ✅ 文本改动不大（大部分句子未变）
- ✅ 需要快速处理大文件
- ✅ 内存受限的环境
- ✅ 校对场景（通常改动较小）

### 不推荐使用

- ❌ 文本改动很大（大量删除/插入）
- ❌ 需要全局最优解
- ❌ 文本顺序变化大

## 使用示例

### 基本用法

```bash
python align_sentences_simple.py -a example/a.md -b example/b.md -o result
```

### 调整参数

```bash
# 增大搜索窗口（处理更大的改动）
python align_sentences_simple.py -a a.md -b b.md -o result --window-size 20

# 提高相似度阈值（更严格）
python align_sentences_simple.py -a a.md -b b.md -o result --threshold 0.7

# 使用trigram（更精确）
python align_sentences_simple.py -a a.md -b b.md -o result --ngram 3
```

### 程序使用

```python
from src.sentence_aligner_simple import align_texts_anchor

alignment = align_texts_anchor(
    text_a="原文...",
    text_b="校对后...",
    window_size=10,
    similarity_threshold=0.6,
    ngram_size=2,
    offset=1
)

for item in alignment:
    if item['type'] == 'match':
        print(f"匹配: {item['a']} <-> {item['b']} ({item['similarity']:.2%})")
    elif item['type'] == 'delete':
        print(f"删除: {item['a']}")
    elif item['type'] == 'insert':
        print(f"新增: {item['b']}")
```

## 性能对比

| 指标             | 锚点算法   | 动态规划算法 |
| ---------------- | ---------- | ------------ |
| 时间复杂度       | O(n × w)   | O(n × m)     |
| 空间复杂度       | O(1)       | O(n × m)     |
| 速度             | ⭐⭐⭐⭐⭐ | ⭐⭐         |
| 内存占用         | ⭐⭐⭐⭐⭐ | ⭐⭐         |
| 准确性（改动小） | ⭐⭐⭐⭐   | ⭐⭐⭐⭐⭐   |
| 准确性（改动大） | ⭐⭐⭐     | ⭐⭐⭐⭐⭐   |

其中：
- n, m: 两个文本的句子数
- w: window_size（通常远小于m）

## 调优建议

### 如果匹配率太低

1. **增大窗口**：`--window-size 20`
2. **降低阈值**：`--threshold 0.5`
3. **使用trigram**：`--ngram 3`

### 如果误匹配太多

1. **提高阈值**：`--threshold 0.7`
2. **减小窗口**：`--window-size 5`

### 如果处理速度慢

1. **减小窗口**：`--window-size 5`
2. **使用bigram**：`--ngram 2`（默认）

## 与动态规划算法对比

| 特性       | 锚点算法     | 动态规划算法 |
| ---------- | ------------ | ------------ |
| 实现复杂度 | 简单         | 复杂         |
| 速度       | 快           | 慢           |
| 内存       | 小           | 大           |
| 准确性     | 高（改动小） | 最高         |
| 适用场景   | 改动小的文本 | 所有场景     |

**建议**：
- 对于改动不大的文本（如校对场景），优先使用锚点算法
- 对于改动较大的文本，使用动态规划算法

## 未来改进方向

1. **自适应窗口**：根据文本改动程度动态调整窗口大小
2. **多锚点**：维护多个候选锚点，提高准确性
3. **回溯机制**：发现错误匹配时能够回溯修正
4. **混合算法**：结合Jaccard和其他相似度算法
